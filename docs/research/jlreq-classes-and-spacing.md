# 日本語縦書きエンジンのための JLREQ 文字クラス・空き量 一次情報調査

最終更新: 2026-09-13

本レポートは、Flutter 上に独自の日本語縦書き（縦組）エンジンを実装するための判断材料として、JLREQ および JIS X 4051 の**文字クラス**・**文字間の空き量**・**分割の可否**・**行頭/行末禁則**・**行の調整処理**を一次情報から整理したものである。

## 0. 出典・調査方法・表記

### 0.1 一次情報

- **[JLREQ]** W3C, *Requirements for Japanese Text Layout 日本語組版処理の要件*, W3C Working Group Note 11 August 2020, <https://www.w3.org/TR/jlreq/>（取得日 2026-09-13）。以下、節番号はこの版に対応する。日本語版は同文書に併記。

- **[JLREQ-C]** 同 付録 C *Possibilities for Line-breaking between Characters 文字間での分割の可否*（`#appendix_3`）。
- **[JLREQ-D]** 同 付録 D *Opportunities for Inter-character Space Reduction during Line Adjustment 行の調整処理で詰める処理が可能な箇所*（`#appendix_4`）。

### 0.2 付録 B〜E の表本体は HTML に無い（重要）

### 0.3 略記

- `½b` / `½a` = 二分アキ（be = 前の文字サイズ基準 / af = 後ろの文字サイズ基準、JLREQ-B §B.1）。

## 2. 文字間の空き量（アキ量） — JLREQ 表1

出典: [JLREQ-B] 付録 B（`#appendix_2`）／[JIS] §4.2 約物の基本的な用法／表PDF `table_ja2.pdf`。

### 2.1 基本規則

JLREQ 表1 の見方（[JLREQ-B] §B.1）:

- **無印（空欄）**: ベタ組（0）。行頭/行末のときは、その文字の前/後ろがベタ。
- **`½ be` / `½ af`**: 二分アキ。`be` は**前に配置する文字**の文字サイズの二分、`af` は**後ろに配置する文字**の文字サイズの二分（サイズが同じならどちらも 0.5em）。
- **`¼ be` / `¼ af`**: 四分アキ（0.25em）。
- **`hang` / `ruby hang`**: ルビのはみ出しを許す。`1/2 be hang` は「二分アキを保持しつつ、行調整前はルビ文字サイズまで掛けてよい」。
- **`×`**: 行頭禁則・行末禁則などにより、その配置自体が禁止。

JIS X 4051 の対応する原則（[JIS] §4.2、JLREQ §3.1.2 も同旨）:

- 始め括弧類（cl-01）の**前**、および終わり括弧類（cl-02）の**後ろ**は **二分アキ**が原則（[JIS] §4.2 b-1）。
- 句点類（cl-06）の**後ろ**は**二分アキ**（[JIS] §4.2 b-2）。
- 中点類（cl-05）の**前後**は**四分アキ**が原則（[JIS] §4.2 c-1）。中点類の次に始め括弧類が続く場合、終わり括弧類の次に中点類が続く場合も四分アキ（[JIS] §4.2 c-2）。
- 始め括弧類が連続、または終わり括弧類が連続する場合は**ベタ**。終わり括弧類の次に始め括弧類が続く場合は**二分アキ**（[JIS] §4.2 d）。
- 句点類の次に終わり括弧類／終わり括弧類の次に句点類は**ベタ**。句点類の次に始め括弧類は**二分アキ**（[JIS] §4.2 e）。
- 行末の終わり括弧類の後ろ、読点類の後ろは**ベタ**。行末の句点類の後ろは**二分**（[JIS] §4.2 f、JLREQ §3.1.9）。JLREQ の推奨は「行末の cl-02 / cl-06 / cl-07 の後ろは二分、ただしベタまで詰めてよい」。

### 2.3 表1 の注記（[JLREQ-B] §B.2、番号は表の `注N` に対応）

### 2.5 表1 の欠落: cl-17 / cl-18

表1 には **cl-17（等号類）と cl-18（演算記号）の行・列が存在しない**。これは JLREQ が数式記号の字間を別節 [JLREQ] §3.7.4（`#processing_of_math_symbols_and_math_operators`）で規定しているためである。要点:

- 字幅は全角。
- 行中（別行でない）の等号類/演算記号と、連数字（cl-24）・欧文用文字（cl-27）・添え字付き親文字（cl-21）との字間は**ベタ**。ただし「これは － 5 となり」「－ a」のように演算記号と連数字/量記号が連続する場合は**四分アキ**。
- 漢字等（cl-19）・平仮名（cl-15）・片仮名（cl-16）との字間は**ベタ**（四分が望ましいとする運用もある）。
- 別行式では等号類と連数字/欧文用文字/添え字付き親文字が**四分**、演算記号とは**ベタ**。分割は等号類の前を優先し、次に演算記号の前。

**Dart 実装上の空白**: 表1 をそのまま 30×30 行列にすると cl-17/cl-18 が未定義になる。§3.7.4 の規則を別関数として実装するか、両クラスを cl-19 相当（ベタ）にフォールバックする必要がある。

### 3.2 表2 の注記（[JLREQ-C] §C.2）

1. `々` を行頭に許容する場合、cl-19 として扱う（cl-19 の欄を参照）。

7. 同一の熟語ルビ以外のルビ付き親文字群（cl-22）内は分割不可、別群なら分割可。
8. 熟語ルビ（cl-23）は親文字群間・同一群内の親文字同士で分割可。ただし 1 字の親文字と対応ルビ文字は一体で分割不可。
9. 連数字（cl-24）と後置省略記号（cl-13）の間は分割不可。`％` は cl-24 との間の分割を許容する方式もあり、その場合 `％` は cl-19 として扱う。
10. 連数字（cl-24）と欧文用文字（cl-27）の間は分割可とする方式と不可とする方式がある。
11. 欧文用文字（cl-27）の後ろの後置省略記号（cl-13）は一般に分割可。ただし前が量記号またはアラビア数字なら分割不可。
12. 欧文用文字（cl-27）同士は分割不可（音節分割＋行末ハイフンで分割）。
13. 同一グループの縦中横（cl-30）内は分割不可、別グループなら分割可。

### 3.3 レベル別の禁則緩和（[JLREQ-C] §C.3 Addendum）

- **レベル1（新聞など・最も緩い）**: cl-03, cl-04, cl-05, 同一種の cl-08, cl-09, cl-10, cl-11, cl-12, cl-13 の前後で分割を許容。

- **レベル3（既定・一般書籍）**: `々`（cl-09）, cl-10, cl-11 の前後で許容（＝行調整回避を優先）。
- **レベル4（一般書籍・最も厳しい）**: 表2 の禁止をすべて適用（緩和なし、行頭の体裁を優先）。

## 5. 行の調整処理

出典: [JLREQ] §3.8（`#line_adjustment`）、§3.8.3（`#procedures_for_intercharacter_space_reduction`）、§3.8.4（`#procedures_for_intercharacter_space_expansion`）、§3.1.9、付録 D/E（表3〜表6）。JIS X 4051 は §4.19 行の調整処理。

### 5.1 詰める処理の優先順位（[JLREQ] §3.8.3）

1. **欧文間隔（cl-26）**を、最小で**四分アキ**まで均等に詰める（対象行の全欧文間隔に同時適用）。
2. 行末の終わり括弧類（cl-02）・読点類（cl-07）・句点類（cl-06）の後ろの**二分アキをベタ**にする。
3. 行末の中点類（cl-05）の前後の**四分アキをベタ**にする。
4. 行中の中点類（cl-05）の前後の四分アキを、最小でベタまで均等に詰める。
5. 行中の始め括弧類（cl-01）の前、終わり括弧類（cl-02）・読点類（cl-07）の後ろの二分アキを、最小でベタまで均等に詰める。
6. S（cl-15/16/19）と W（cl-24/25/27）の間の四分アキを、最小で**八分アキ**まで均等に詰める。

補足（§3.8.3 の Note）:

- 句点類（cl-06）の後ろの二分アキは文の区切りとして重要なので、行末に配置する場合を除き**調整に使用しない**。
- 始め括弧類の前・終わり括弧類の後ろの二分アキをベタまで詰めるのは詰め過ぎとして、最小**四分アキ**までとする運用もある。
- S と W の四分アキを固定空き量として調整対象にしない運用もある。

JIS X 4051 準拠の順序（§3.8.3 後半）:

1. 欧文間隔（cl-26）を最小四分まで。
2. 中点類（cl-05）の前後四分を最小ベタまで。
3. 始め括弧類（cl-01）の前、終わり括弧類（cl-02）・読点類（cl-07）の後ろの二分を最小ベタまで。
4. S と W の四分を最小八分まで。

### 5.2 空ける処理の優先順位（[JLREQ] §3.8.4）

1. **欧文間隔（cl-26）**を、最大で**二分アキ**まで均等に空ける。
2. S と W の間の四分アキを、最大で二分（または三分）まで均等に空ける。
3. (1)(2) 以外で分離禁止でない箇所を、最大で**四分アキ**まで均等に空ける。
4. (1)〜(3) で調整できない場合、分離禁止でない文字間を均等に空ける（欧文用文字 cl-27 の字間を含めるかは処理系定義）。

第4段階が必要な場合は、第1〜3段階で入れた空き量に追加して、第1〜4段階の箇所を均等に空ける（§E.1）。

### 5.3 表3〜表6（調整可能箇所）の概要

付録 D/E の表記（[JLREQ-D] §D.1、[JLREQ-E] §E.1）:

- **白地（□）/無印**: 空け・詰めの対象外（ベタ、または規則により調整不可）。

- 表6 には**行頭・行末の欄が無い**（行頭の前・行末の後ろは空け対象にしないため）。

### 6.2 既定の空き量マップ（em）

`be`/`af` の区別は、行中に異なる文字サイズが混在する場合にのみ意味を持つ（[JLREQ-B] §B.1）。等サイズなら `be == af` なので、実装は次の 3 値を基本にすればよい。

- `0.0` = ベタ
- `0.25` = 四分
- `0.5` = 二分
- `1.0` = 全角（文末の区切り約物の後ろなど、cl-14 を挿入して表現）

以下は §2.1 の規則と JIS §4.2 をそのままコード化した既定値生成器である。`cl-06→cl-05` や `cl-05→cl-05` のように「前分＋後ろ分」が加算されるケースも、**合算後の総アキ**を返す形にしてある（表1 の欠落を補うため cl-17/cl-18 は一旦ベタにフォールバックし、§3.7.4 の規則で上書きする）。

```dart
bool _isJa(JlClass c) =>
    c == JlClass.cl15Hiragana ||
    c == JlClass.cl16Katakana ||
    c == JlClass.cl19Ideographic;

bool _isLatin(JlClass c) =>
    c == JlClass.cl24GroupedNumeral ||
    c == JlClass.cl25UnitSymbol ||
    c == JlClass.cl27WesternChar;

/// JLREQ 表1 / JIS X 4051 §4.2 の規則を優先順に評価する既定空き量。
/// 戻り値は em。0.0=ベタ / 0.125=八分 / 0.25=四分 / 0.5=二分 / 1.0=全角。
double defaultSpacingEm(JlClass before, JlClass after) {
  // (1) 後ろが始め括弧類: その前は二分（表1 cl-01 列の ½a）。
  if (after == JlClass.cl01OpeningBracket) {
    return before == JlClass.cl01OpeningBracket ? 0.0 : 0.5;
  }
  // (2) 後ろが中点類: その前は四分（表1 cl-05 列の ¼）。句点/読点の後ろは二分を加算。
  if (after == JlClass.cl05MiddleDot) {
    return switch (before) {
      JlClass.cl06FullStop || JlClass.cl07Comma => 0.75, // 二分＋四分（注5）
      JlClass.cl05MiddleDot => 0.5,                      // 四分＋四分（注3）
      _ => 0.25,
    };
  }
  // (3) 和欧混植（S⇄W）は四分（§3.1.10 Figure 84 の慣習）。
  if ((_isJa(before) && _isLatin(after)) ||
      (_isLatin(before) && _isJa(after))) {
    return 0.25;
  }
  // (4) 前に着目した後ろアキ。
  return switch (before) {
    // 終わり括弧類の後ろは二分。句点/読点/終わり括弧/和字間隔の前はベタ。
    JlClass.cl02ClosingBracket => switch (after) {
        JlClass.cl02ClosingBracket ||
        JlClass.cl06FullStop ||
        JlClass.cl07Comma ||
        JlClass.cl14IdeographicSpace => 0.0,
        _ => 0.5,
      },
    // 句点類・読点類の後ろは二分。ただし終わり括弧/句点/読点の前はベタ。
    JlClass.cl06FullStop || JlClass.cl07Comma => switch (after) {
        JlClass.cl02ClosingBracket ||
        JlClass.cl06FullStop ||
        JlClass.cl07Comma => 0.0,
        _ => 0.5,
      },
    // 中点類の後ろは四分（(2) で前側も処理済み）。
    JlClass.cl05MiddleDot => 0.25,
    // ハイフン類・区切り約物の後ろ、和字間隔・数学記号などの後ろはベタ。
    _ => 0.0,
  };
}
```

> この関数は**規則ベースの近似**である。表1 の全セル（特に cl-12/13・cl-21〜cl-25・ルビ付き親文字の `hang`）を網羅するわけではないので、最終的な既定値は §6.4 の eighths 行列（表1 の再構成値）と突き合わせて確定すること。`×`（配置禁止）と `hang` は空き量ではないため、それぞれ禁則判定・ルビレイアウト側で扱う。

### 6.3 実装上のギャップ（要対応）

1. **cl-17 / cl-18 の空き量**: 表1 に列が無い。§3.7.4 の規則（行中はベタ、連数字/量記号との連続時は四分、別行式では等号類と数字が四分）を別関数で実装する必要がある。
2. **`be`/`af` の文字サイズ依存**: ルビ・縦中横・外字などで行内に異サイズが混在すると、二分/四分の基準が前後で変わる（§B.1 Figure 316）。`defaultSpacingEm(before, after, beforeSize:, afterSize:)` の signature で保持している。
3. **ルビのはみ出し（hang）**: 表1 の `hang`/`ruby hang` は空き量ではなく「ルビが隣接文字に掛かる許容量」であり、空き量マップとは別に ruby レイアウト側で扱う（注1,7,8、[JLREQ] §3.3）。
4. **行頭/行末の特別値**: 行末 cl-02/05/06/07、行頭 cl-01 は表1 の `line-end`/`line-head` で別扱い。文字ペアだけでなく「行内位置」を引数に取る必要がある。
5. **禁則（×）と分割可否（表2）**: 空き量マップとは独立に、表2 の `不可`/`×` と §3.3 の 4 レベルを実装する。禁則緩和レベルはオプション化する。
6. **行の調整**: 表3〜表6 の調整可能箇所と優先順位（§5.1/§5.2）、および §3.1.11 の分離禁止は、空き量マップから**調整フラグ付き**で導出する。行頭は詰め対象外、行末句点の二分は詰めない点に注意。
7. **割注（cl-28/cl-29）と縦中横（cl-30）**: 表1/表2 で `×` や文脈依存が多く、専用処理（[JLREQ] §3.6 割注、§3.8.8 縦中横）が必要。
8. **再構成の不確実性**: §0.2 のとおり、表1〜表6 の一部セルは PDF からの座標再構成値。実装前に `table_ja2.pdf`〜`table_ja7.pdf` で検証することを推奨。
